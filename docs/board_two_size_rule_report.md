# 棋盘两档砖块尺寸规则

更新时间：2026-07-06

## 用户观察

竞品棋盘的尺寸逻辑不是每关连续缩放，而是接近两档：

- 横向常规距离：最多约 `6` 个砖。
- 横向最大距离：最多约 `7` 个砖。
- 纵向常规距离：最多约 `7` 个砖。
- 纵向最大距离：最多约 `8` 个砖。
- 因此砖块不应该每关忽大忽小，只应该有“大砖 / 小砖”两种主要尺寸。
- 砖块可以通过层级实现半遮挡、一角遮挡、全遮挡；但棋盘平面尺度本身不应无限扩张。
- 棋盘左右视觉边界应与上方 hub 槽左右对齐。

## 已落地的代码规则

### 1. `UILayoutConfig.ts`

新增/调整：

```ts
board: {
    widthRatio: 0.90,
    normalVisualCols: 6,
    normalVisualRows: 7,
    maxVisualCols: 7,
    maxVisualRows: 8,
}
```

含义：

- `6 × 7`：常规棋盘，用大砖。
- `7 × 8`：最大棋盘，用小砖。
- 棋盘宽度与 hub 槽同为 `0.90`，保持左右对齐。

### 2. `BoardManager.ts`

`computeTileSize()` 已改为两档逻辑：

```text
如果实际结构能放进 6×7：
  使用 largeSize
否则：
  使用 smallSize
如果结构超过 7×8：
  仅作为安全兜底继续缩小，避免越界
```

这意味着正常合规关卡只会出现两种砖块尺寸。

## 当前估算结果

按当前测试关 `Level 1-20` 估算：

- 大砖尺寸：约 `148.4`
- 小砖尺寸：约 `127.4`

但是当前测试关里有多关结构超过了 `7×8` 最大视觉包围盒，触发了安全兜底缩小，因此出现了 `119 / 111 / 105 / 99 / 94` 等尺寸。

这说明：

> 两档尺寸规则已经在代码里支持，但测试关结构还没有完全按“最大 7×8”重新约束。

## 堆叠方向规则更新

用户进一步确认：竞品的堆叠方向不应被限定为固定右上。

现在代码已支持：

- `layerStepDirX / layerStepDirY`：每张高层砖可单独指定 360° 任意偏移方向。
- `layerStepCoef`：控制偏移幅度；`0` 可以实现 100% 覆盖，`0.1` 是 90% 覆盖，`0.5` 是半格错位。
- `stackTowardCenter`：保留为快捷模式；未显式指定方向时，可朝棋盘中心偏移。

测试关 `Level 1-20` 已给高层砖写入显式方向：

- 最左侧砖向右侧/中心偏。
- 最右侧砖向左侧/中心偏。
- 顶部砖向下方/中心偏。
- 底部砖向上方/中心偏。
- 中部砖允许多方向偏移。

### 1. 层级偏移仍然需要纳入真实视觉 bbox

即使底层网格看起来是 `7` 列，高层砖块如果向外偏移，真实视觉 bbox 仍可能超过 `7` 砖宽。

所以后续设计棋盘时，不能只看 `rows / cols`，还要看层级偏移后的实际视觉 bbox。边缘砖原则上应向中心偏，中部砖才适合自由方向。

### 2. 结构超出 7×8 会破坏“两档尺寸”

如果某个测试结构太宽或太高，代码会为了不越界继续缩小砖块。

这不是目标体验，只是安全兜底。

后续测试关应该调整到：

```text
常规结构 <= 6×7 → 大砖
最大结构 <= 7×8 → 小砖
超过 7×8 → 结构不合格，需要重做
```

## 当前判断

方案可以实现，但需要两件事同时成立：

1. **代码层**：砖块尺寸只按 `6×7 / 7×8` 两档计算。已完成。
2. **关卡层**：测试关结构必须控制在 `7×8` 最大视觉包围盒内。当前未完全满足，需要下一步重排测试关。

- `UILayoutConfig.ts` 无 linter 错误。
- 关键配置存在：`normalVisualCols / normalVisualRows / maxVisualCols / maxVisualRows`。
- 关键逻辑存在：`largeSize / smallSize / fitsNormal / safeSize`。
