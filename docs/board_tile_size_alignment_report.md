# 棋盘砖块尺寸与 hub 槽对齐方案

更新时间：2026-07-06

## 背景

用户观察竞品截图后提出：

- 横向常态最多约放 6 个砖。
- 此时的砖块大小就是大部分关卡里看到的常态砖块大小。
- 棋盘左侧、右侧应与上方 hub 槽左右对齐。
- 如果棋盘继续按小结构 bbox 自动放大，第 4 关这类局部塔会显得砖块异常大。

## 结论

该方案可以实现，而且比之前“完全按当前关卡 bbox 自适应”更适合关卡设计测试。

核心改法：

```text
棋盘可用宽度 = hub 槽宽度
小棋盘尺寸上限 = 按 6 个横向砖计算得到的常态砖块大小
大棋盘 / 超过 6 砖宽的棋盘 = 继续按实际 bbox 缩小，保证不越界
```

这样可以同时满足：

1. 小棋盘不会因为 bbox 太小而砖块过大。
2. 大棋盘不会越界，会自动缩小。
3. 棋盘左右边界与 hub 槽保持同一视觉宽度。
4. 第 4 关局部高塔不会再比相邻关卡突兀放大。

## 已修改文件

### 1. `assets/scripts/ui/common/UILayoutConfig.ts`

新增配置：

```ts
board: {
    widthRatio: 0.90,
    maxVisualCols: 6,
}
```

含义：

- `widthRatio: 0.90`：棋盘主视觉宽度与 hub 槽一致。
- `maxVisualCols: 6`：横向 6 个砖作为常态视觉基准；小棋盘不再继续放大。

### 2. `assets/scripts/game/board/BoardManager.ts`

调整 `computeTileSize()`：

- 宽度从原来的 `availableWidth - margin * 2` 改为 `availableWidth * board.widthRatio`。
- 计算尺寸时使用：

```text
sizingWidth = max(实际棋盘 bboxWidth, 6 砖参考宽度)
```

因此：

- 实际 bbox 小于 6 砖宽 → 按 6 砖宽计算，避免过大。
- 实际 bbox 大于 6 砖宽 → 按实际 bbox 计算，避免越界。

## 与之前的差异

之前第 4 关估算 tileSize 约 `161`，接近上限，明显偏大。

现在第 4 关估算 tileSize 约 `148.4`，与第 1、2 关一致，属于“横向 6 砖常态尺寸”。

对于第 5、8、9 关这类更宽的结构，仍然会自动缩小，避免越出 hub 槽宽度。

## 可能的问题与边界

1. **极宽棋盘会更小**  
   这是预期行为。如果结构横向超过 6 砖宽，必须缩小，否则会越界。

2. **极高棋盘仍受高度限制**  
   如果某关纵向堆叠很高，`availableHeight / bboxHeight` 仍然会限制砖块大小。

3. **传送带 / 料仓机制会继续挤占宽度**  
   如果未来重新启用侧边机制，`bandReserveLeft/Right` 仍会从棋盘宽度里扣除，棋盘会相应缩小。

4. **这次没有改关卡结构**  
   只改了棋盘尺寸计算逻辑；1-20 测试关结构未因此变化。
